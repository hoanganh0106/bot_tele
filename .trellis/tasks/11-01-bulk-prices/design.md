# Design

Implement a standalone Python 3 standard-library maintenance CLI in tools/bulk_prices.py. The production bot stays Rust; Python is only a portable operations utility already available on the server. No new admin network endpoint or credentials are introduced.

Commands: export fetches fresh supplier product quotes and joins current pricing state; plan builds an explicit before/after price-delta plan from an export and JSON changes; apply defaults to preview and requires --execute to write. A service argument defaults to ctv-bot in production. Offline fixture operation is available for tests through pure functions, not an unsafe running-bot bypass. A receipt and full JSON backup are generated on apply. Agent rollback uses a new inverse price-only plan after checking receipt, never overwrites live data with an old full database.

Export fields include key, name, source, supplier_cost_vnd (null for local), base_price_vnd, selling_price_vnd, effective_markup_vnd, delta_override_vnd (null when absent), default_markup_vnd, usdt_override and fetched timestamp. Derive effective price from settings.default_markup_fixed (Rust default 10000), local base, price_deltas; custom_prices is legacy and ignored by Rust. Preserve existing USDT overrides and flag their independence. Fetch CTV GET /api/dealer/stock and Hypervin GET /api/products with X-API-Key; never call buy endpoints or return secret values.

Each change uses key plus exactly one of selling_price_vnd, markup_vnd or reset=true. Target selling price becomes delta relative to the exported current base; resets remove only the selected override. Validate integer monetary values within signed i64 and positive resulting selling price. Plans include selected expected input state and freshness metadata; apply refetches suppliers and rejects changed selected base/override/default or expired plans. Re-read latest state after service stop; mutate only selected price_deltas, backup, fsync temporary JSON, atomic replace, verify, restart in finally and validate service. State remains authoritative in the running process, so direct editing while running is prohibited.

Use strict JSON validation, output files distinct from database/config/input, fixed service name validation, safe API error messages and no secret content. Record metadata sufficient to audit/undo selected price overrides only. No actual price changes occur during deployment validation.
